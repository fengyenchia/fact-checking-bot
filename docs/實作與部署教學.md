## 1. 本機先跑

依 README 啟動專案。還沒連 Neon 時，可以用固定案例和模擬回覆試跑。 [本機啟動](../README.md#本機啟動) · [門票測試劇本](門票測試劇本.md)

## 2. 在 Neon 建立資料庫

本機與 Vercel 共用同一個 Neon 分支和資料庫。

1. 登入 Neon Console。首次使用就建立 Postgres Project，已有 Project 就選原本的分支與資料庫。 [Neon Console](https://console.neon.tech/)
2. 在 **SQL Editor** 選定該分支與資料庫。首次初始化時，貼上 `schema.sql` 全文並執行。 [初始化 SQL](../lib/server/schema.sql)
3. 在 **Connect** 選同一個分支與資料庫，複製完整的 PostgreSQL pooled connection string，供第 4 節設定 `DATABASE_URL`。 [Neon 連線教學](https://neon.com/docs/connect/connect-from-any-app)

<details>
<summary>已有資料庫才看：檢查舊版欄位</summary>

在同一個 **SQL Editor** 執行下方唯讀查詢。回傳 0 筆表示這六個欄位都存在。有結果時，每列會列出一個缺少的欄位。

```sql
SELECT required.table_name, required.column_name
FROM (VALUES
    ('cases', 'source_date'),
    ('cases', 'source_city'),
    ('cases', 'card_summary'),
    ('suspicious_accounts', 'case_status'),
    ('suspicious_accounts', 'lookup_count'),
    ('suspicious_accounts', 'source_url')
) AS required(table_name, column_name)
WHERE NOT EXISTS (
    SELECT 1
    FROM information_schema.columns AS actual
    WHERE actual.table_schema = 'public'
      AND actual.table_name = required.table_name
      AND actual.column_name = required.column_name
);
```

- 缺少 `card_summary`、`case_status`、`lookup_count` 或 `source_url` 時，執行最新版的 `schema.sql` 補欄位。 [最新版 schema.sql](../lib/server/schema.sql)
- 若舊 `cases` 表缺少 `source_date` 或 `source_city`，需另外補欄位，並依原始來源補填既有案例的發布日期與縣市。
- 舊可疑帳號表的 `reason` 是已停用的「列入依據」。請在 Neon **SQL Editor** 選擇 Demo 使用的分支與資料庫，貼上以下 SQL 並按 **Run**。這會刪除此欄位及其中的舊資料，執行後重新整理 **Tables → suspicious_accounts** 即可確認。 [舊版可疑帳號清理 SQL](../lib/server/migrations/simplify-suspicious-accounts.sql)

```sql
ALTER TABLE public.suspicious_accounts DROP COLUMN IF EXISTS reason;
```

可重複執行這段 SQL。目前帳號表使用的欄位為 `id`、`case_status`、`lookup_count`、`source_url` 和 `updated_at`。

## 3. 建立 OpenAI 金鑰

1. 在 OpenAI Platform 建立 Demo 專用的 Project，從該 Project 的 **API Keys** 建立金鑰。 [OpenAI Project 設定](https://platform.openai.com/settings/organization/projects)
2. 若有 API 額度，確認已入帳並查看到期日。在 Project 的 **Limits** 設定預算與通知。 [OpenAI 專案預算](https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform)

## 4. 設定環境變數與部署到 Vercel

- `DATABASE_URL` 填 Neon 的完整 pooled connection string，保留連線參數。
- `OPENAI_API_KEY` 填剛建立的完整 Project API 金鑰。連結 AI 補查使用這把金鑰，聊天回覆與案例檢索還需要 `DATABASE_URL`。
- `ADMIN_PASSWORD` 填自行設定的非空密碼，用於 `/admin/login`。
- `ADMIN_SESSION_SECRET` 填下方指令輸出的金鑰。簽署金鑰至少 32 字元，每個環境各產生一組。
- `OPENAI_MODEL` 選填，覆寫 AI 回覆和案例欄位生成使用的模型。這兩項預設為 `gpt-6-luna`，連結 AI 補查固定使用 `gpt-6-luna`。

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

1. **在本機**，到專案根目錄把 `.env.example` 複製成 `.env.local`。已有 `.env.local` 時直接編輯。填好前四項後重新執行 `pnpm dev`。 [環境變數範本](../.env.example)
2. **在 Vercel**，從 GitHub 匯入專案，Framework Preset 選 **Next.js**。在 **Settings → Environment Variables** 分別新增前四項，每筆選 **Production** 並填入原始值。若也用 **Preview**，在該環境設定相同的四個變數名稱，並共用 Neon 連線字串。 [Vercel 環境變數設定](https://vercel.com/docs/environment-variables/managing-environment-variables)
3. 首次部署按 **Deploy**。已有部署時，到 **Deployments** 選 **Redeploy**，讓新的環境變數生效。

真實值填在 `.env.local` 或 Vercel 的環境變數設定。變數名稱維持上方寫法。

## 5. 收錄案例與正式試跑

1. 用部署網址開 `/admin/login`，登入後到 `/admin/cases` 新增案例，按「更新首頁案例卡」，再回首頁確認卡片。到 `/admin/accounts` 加入測試用的 `giveme_money`，填入案件狀態、測試用查詢人數和資料連結。
2. 用手機開 Vercel 正式網址跑一次門票劇本，送出 Widget 查證，確認有 AI 回覆，再到 `/admin` 核對輸入與回覆紀錄。
3. 分別測試已知服務、TWNIC 快照中的完整網址、現有清單品牌的仿冒案例及 AI 補查。核對成功時的大標應為「已核對」，服務或商店名稱顯示在來源欄。確認「潛在風險」與「曾被通報」底部都有數發部通報按鈕。完整測試項目見 [測試內容與資料準備](測試內容與資料準備.md)。

在 Neon 直接新增或修改案例後，到後台按「重新讀取案例」。頁首顯示本次載入的案例總筆數，清單包含草稿與已收錄案例。核對 Neon **SQL Editor** 使用的分支與資料庫和網站 `DATABASE_URL` 一致，再以以下查詢比較筆數。

```sql
SELECT count(*) AS total FROM public.cases;
```
