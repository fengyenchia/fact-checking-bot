# 對話評估｜AI 與 RAG

## 目前流程

1. 受測者逐句勾選賣家訊息。伺服器用訊息 ID 還原原文，防止前端偽造文字；ID 不參與風險判斷。
2. 只用勾選原文檢索 Neon 案例，綜合語意、商品及手法取最多三筆。沒有提到門票時，不自動指定門票情境。
3. 將勾選原文、檢索案例標題與原文交給 AI。沒有傳入賣家名稱、帳號、劇本標籤或未選的訊息。
4. AI 一次回傳風險層級、短建議、最多四個疑點的原文證據與理由，以及相關案例 ID。
5. 伺服器驗證原句證據，再透過與快速對話共用的函式確認案例 ID 來自本次檢索。引用不存在、格式不符或模型失敗時，回傳可重試的錯誤。
6. 共用函式去除重複案例並保留 AI 的順序，最多三張、置底橫向滑動；沒有相關案例則省略整區。[兩功能共用流程](案例檢索與AI選卡.md)

## 不限付款或驗證

範圍限於網購、社群買賣、二手商品、演唱會門票或周邊交易，以及相關付款、退款、物流與售後客服。評估原文中的可疑目的、要求行動、矛盾說詞、壓迫手段與可能損害，不是關鍵字命中數。

指令中的例子包括假買家／賣家、假平台客服、超低價或假商品、虛假訂單、收款不出貨、誘導離開平台、假退款、付款驗證、再匯款、假物流與取貨通知、索取資料或驗證碼、假客服要求安裝遠端工具等。這些是開放式參考，也可辨識未列出的網購詐騙手法。

- **極高風險**：具體明確、可能造成重大損害的可疑要求或誘導。
- **潛在風險**：有可疑操作或說詞，但關鍵脈絡不足。
- **線索不足**：一般詢問、防詐提醒、否定可疑要求或資料不足；不表示交易安全。明確非網購題目也回傳此類，並引導回網購查證，不引用案例。

AI 仍可能誤判。引用檢查只確認「原句存在」，無法證明模型對該句的解讀一定正確。相關案例提供比較依據，不能把案例中的情節當成受測者已經遇到的事。

## 失敗與紀錄

- 沒有案例：仍可依原文評估，不強迫湊三張，也不因無案例判成安全或高風險。
- RAG 未完成或沒有 Neon：有 OpenAI 金鑰時仍可評估，後台標記本次僅依內容判斷。
- 沒有 OpenAI 金鑰、逾時、拒答、回覆不完整或引用不符：提示重試，保留勾選，不使用劇本風險或本機固定判斷。
- 後台保存風險層級、引用句、理由、案例 ID 與檢索狀態。沿用既有 JSON 欄位，不用追加 SQL。
- 舊紀錄保留，Widget 遇到舊版結果會要求重新評估。重新送出成功後使用新結果。

## 驗證方式

執行 `pnpm test`，或直接執行：

```powershell
node --test tests/dialogue-assessment.test.mjs
```

自動化測試使用模擬服務，不載入 `.env.local`，不呼叫 OpenAI 或 Neon。涵蓋 ID 不影響風險、假買家索驗證碼、超低價商品說詞、RAG 失敗、無案例、捏造引用、AI 拒答或失敗，以及三種結果畫面。這能驗證程式流程，不能代替真實 AI 品質測試。

正式試跑時，先用現有聊天室只勾一般問候，再勾再次付款與退款承諾，確認不同內容不會一律得到極高風險。其他手法可在本機暫改 [劇本原文](../data/scenarios/ticket.ts)，並更新 `scenarioVersion` 後建立新場次，以免沿用舊進度。

真實模型仍待複核以下情況：

- 一般問候：應為線索不足，不因賣家名稱提高風險。
- 要求再付款並承諾退前款：應辨識重複付款風險及具體原句。
- 假買家以開通賣場收款為由索取驗證碼：應能辨識冒充客服與帳戶風險。
- 超低價商品且拒絕實拍、阻止向原賣場詢問：應能辨識付款前的商品與交易疑點。
- 「別給任何人驗證碼，也不要再次付款」：應辨識防詐提醒，不因關鍵字誤判。
- 未見過的網購誘騙手法：依要求行動及損害評估，不必先新增關鍵字規則。
- 明確非網購問題：應引導回網購詐騙查證，不展開其他領域分析。
- 無案例與 RAG 暫時失敗：仍可依內容評估；後台的檢索狀態須正確。
