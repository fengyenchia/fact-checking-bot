# 案例檢索與 AI 選卡

- **共用流程**：快速對話與對話評估皆為「RAG 初選 → AI 篩選 → ID 驗證 → 顯示最多三張」。
- **畫面**：案例卡放在該輪輸出的最底下，橫向滑動；沒有適合案例時省略案例區與空資料提示。
- **範圍**：只處理網購、社群買賣、門票、二手商品及相關交易手法。

## 兩個功能的輸入與輸出

| 功能 | RAG 初選輸入 | 同一次 AI 請求回傳 |
| --- | --- | --- |
| 快速對話 | 本輪文字＋同場最近兩筆成功問題。 | 短回答 `answer`、操作 `suggestedActions`、案例 `caseIds`。 |
| 對話評估 | 使用者勾選的對方原文。 | 風險層級、短建議、原句證據、理由及 `caseIds`。 |

## 選卡步驟

1. RAG 依語意、商品及手法，從 Neon 找最多三筆候選。
2. AI 讀取本輪內容與候選原文，選出真正相關的零至三個案例 ID，依相關程度排序。
3. 伺服器確認每個 ID 都來自本次候選；不存在的 ID 或超過三筆的輸出視為失敗。
4. 共用函式去除重複 ID，依 AI 順序取出資料庫原有的卡片標題、摘要與來源。
5. 將最終案例卡保存到該輪紀錄並顯示；AI 不生成新的案例卡原文或任意網址。

## 範圍與失敗處理

- 改問其他商品時，以本輪問題為主；前文只補脈絡，不沿用已不相關的商品案例。
- 沒有相關候選或 AI 全部排除時，仍可回覆建議，卡片顯示零張。
- RAG 失敗時，兩功能皆可依提交內容繼續回答，後台保存檢索未完成狀態；不附案例卡。
- AI 失敗、回答格式錯誤或選到不存在的案例 ID 時，提示重試並保留輸入；不直接展示未經 AI 選中的 RAG 候選。
- 未設定完整 AI＋Neon 時，快速對話只提供本機預覽建議，不附固定案例卡；首頁原有的預覽卡保留。
- 快速對話的回答、操作與選卡在同一次生成請求完成，不另開一次選卡請求。
- AI 仍可能誤判相關性，正式測試須人工複核；ID 檢查只能確認案例確實來自本次檢索。

## 驗證與部署

- 執行 `pnpm test`，包含案例排除、AI 順序、重複 ID、偽造 ID、超額選卡、改問商品、無案例與 API 失敗等測試。
- 測試使用模擬 AI 與資料庫，不讀取 `.env.local`，不使用 API 額度。
- 新資料沿用 `widget_submissions.response` 的 JSON 欄位，不需要新增 SQL；重新部署即可。
- 舊紀錄保留原有輸出，新規則適用於重新提交的查證。
- 真實 AI＋Neon 的相關性仍待實測驗收，模擬測試不代表真實模型一定選得正確。
