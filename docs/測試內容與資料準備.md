# 測試內容與資料準備

## 先定第一篇與聊天室

- 採用 [門票測試劇本](門票測試劇本.md) 的三篇串文、帳號及對話，模擬帳號使用橘色圓形頭貼。只有門票帳號 `@giveme_money` 會進入測試聊天列表及聊天室。
- 第二、三篇日常串文已寫在劇本。門票劇本可參考 [作業一的田野與訪談](https://docs.google.com/document/d/167mzJxtOMmyO0XW3kmQ_oksAXeon7umW4QfVIuF0fXM/edit?tab=t.u8fvt3g89wbe)。
- 只準備一份門票聊天室劇本。先顯示固定歷史訊息，預填「轉好帳了」，受測者送出後逐條顯示賣家的可疑訊息。每則記錄 ID、發送者、文字、順序與出現條件，賣家的句子逐句可勾選。
- 劇本用模擬帳號和資料。若需顯示可疑網址，可用不可連線的示例網域並以純文字呈現。參考截圖用於比對版面。

## 再整理官方案例

1. 先複核試算表中與劇本最接近的門票案例，尤其是轉帳失敗、要求再付款和假客服。也保留其他商品的個案，供小客服測試跨商品檢索。[30 筆候選試算表](官方案例候選30筆.xlsx)
2. 依試算表的「發布日期」和「發布縣市」回查原文。儀錶板以查詢頁展開個案，所以這批案例共用同一個來源網址。若同日同縣市有多筆，用標題或摘要中的具體線索對照原文。[165 打詐儀錶板｜各縣市每日案例](https://165dashboard.tw/city-case-summary)
3. 完成 Neon 初始化與 OpenAI 金鑰設定後，到 `/admin/cases` 填商品類別、案例原文、發布日期、發布縣市。日期可填民國年或西元年。來源機關與網址已預填，可依實際來源修改。試算表的標題、摘要、手法標籤與收錄狀態供複核。儲存時，AI 會依原文產生標題、標籤與卡片短摘要，系統隨即建立檢索向量。列表可展開原文並查看短摘要。[實作與部署教學](實作與部署教學.md)
4. 為測試準備幾組輸入及預期結果，涵蓋「有高度相關個案」、「只有類似手法」和「資料不足」。儲存案例後，到 Widget 核對檢索結果。

後台儲存成功後會加入檢索，案例清單顯示總筆數並包含草稿與已收錄資料。Neon 直接修改後按「重新讀取案例」重新載入。Widget 實際檢索還會檢查向量、來源與相關程度。

## 上線測試前

- 在 `/admin/accounts` 新增模擬 Threads 帳號 `giveme_money`。案件狀態填「核實中」時，結果大標應為「潛在風險」。另查未收錄的帳號，結果應只顯示「目前查無此帳號的資料。」。
- 優先準備三筆不同且有來源的門票案例，在後台按「更新首頁案例卡」。驗證首頁只在第一篇門票串文下方顯示這批卡片，首頁與 Widget 都最多顯示三張，資料不足時顯示實際找到的筆數。
- 用「快速對話」測試自由輸入與追問，包括目前商品、改問另一類商品及案例庫不足。兩功能都先經 RAG 初選，再由 AI 選零至三張，依 AI 順序置底橫向顯示；不適合的候選不顯示。到後台核對問題、回答及最終案例。[共用選卡流程](案例檢索與AI選卡.md)
- 測試 AI 全部排除、回傳重複 ID 或不存在的 ID。應去除重複；不存在或超額選卡時提示重試，不回退顯示原始 RAG 候選。RAG 失敗仍可回答，但不附案例卡並保存檢索狀態。
- 未同時設定 AI 與 Neon 時，快速對話只有本機預覽建議，不放固定案例卡；首頁預覽卡不受影響。
- 官方案例聚焦網購、社群買賣、二手商品、門票與周邊交易，不限付款驗證：涵蓋假買家／賣家、假平台客服、超低價或假商品、收款不出貨、退款、物流、索取資料及誘導離開平台等手法。原文需清楚描述「對方要求做什麼、用什麼理由、可能造成什麼損害」。

- 定每場的任務文字和觀察項目，例如是否主動打開 Widget、勾選了哪些訊息、能否說出疑點及下一步。
- 用各自的手機開啟 Demo，核對重整會延續聊天室進度。用預覽的「重新開始」確認畫面從頭載入且舊紀錄可在後台查閱。開啟 Widget 後確認先顯示四種方式。逐一送出並用右下角返回選單，確認未送出的草稿可續填、快速對話可繼續追問。
- 手機檢查 Widget 頂部標題可見、選單和插圖可上下捲動、底部操作可點擊。按住黃色、黑色按鈕時應立即變色。讀取插圖會預載，切換功能頁和結果時有短淡入動畫，系統的減少動態效果設定應生效。
- 對話評估直接進入訊息勾選，白色選取區、提示和面板四角為 20 px。送出後使用對話插圖，讀取提示文字持續上下跳動；系統啟用減少動態效果時停止跳動。結果列出重點，相關案例顯示在最底下。
- 對話風險必須來自勾選原文＋AI＋RAG，不是訊息 ID。先只勾一般問候，預期線索不足；再勾重複付款與退款承諾，核對較高風險與引用理由。後台原句必須確實出現在本次選取內容，不能借用未選訊息或案例中的情節。
- 另外複核超低價商品、假買家／賣家、防詐提醒、否定句、新網購手法及無案例狀況。模型提示允許未列出的網購手法，案例不足仍可分析；非網購問題引導回查證範圍，模型品質需人工校正。[對話評估驗收說明](對話評估_AI與RAG.md)
- 帳號與連結查證的讀取圈位於標題下方。查核結果採獨立畫面，結論用最大字級。錯誤提示為 16 px 橘色。
- 試送格式無效的網址及模擬連線失敗，確認網址留在輸入欄供修正或重試。另模擬 AI 說明逾時，確認已完成的帳號、網址結果照常顯示。對話評估本身依賴 AI，逾時或拒答時應顯示錯誤並保留勾選，不回傳固定風險。
- 驗證管理員登入後能查閱和編輯。未登入時攔截管理頁與管理讀寫請求。
- 用管理頁核對 Widget 每筆送出的內容與 Bot 回覆是否成對保存。提交紀錄永久保留，開啟和取消勾選等操作不另存事件。
- 用一場試測檢查手機版返回動線、勾選與取消、結果來源、重複提交，以及能否從後台找回這一場的紀錄。

### 連結查證試跑

- 輸入 `123`，直接在原輸入頁顯示「連結無效，請重新輸入！」，不送出 API，也不進結果頁。
- 輸入 `https://mall.iopenmall.tw/`，未命中 TWNIC 時，大標應顯示「安全」，來源為「iOPEN Mall」。
- 從 [TWNIC 本機快照](../data/通報TWNIC詐騙網址彙整表_20261008.json) 選一筆可解析的主網域，直接貼到 Widget。結果應顯示「有通報紀錄」。換成同主網域下的其他次網域、路徑或參數，仍應命中；不要實際開啟清單網址。
- 通報結果說明應指出該主網域出現在清單，不表示當前完整網址曾被通報。主網域文字只出現在另一網域的路徑、查詢參數或相似名稱時，不應誤判命中。
- 輸入劇本的 `https://myship.payment-check.invalid/`，應顯示「有問題喔」和主網域不符原因。「有問題喔」與「有通報紀錄」底部均應有「前往數發部通報」。
- 輸入未列入清單且無品牌仿冒線索的網址，例如 `https://www.ilovepdf.com/zh-tw`，應顯示「無法確認」。AI 只補原因及建議，不搜尋新來源或變更結論。
- 品牌仿冒測試使用 [現有清單](../lib/server/official-hosts.ts) 的品牌別名。
- 檢查大標與狀態均顯示對應判定。黃色色塊顯示完整主機、主網域及次網域，橘色和藍色色塊分別顯示來源及狀態。
- 本機執行 `pnpm test`：包含 TWNIC 優先於已知服務、主網域邊界、四種結果與 AI 說明失敗測試；使用本機資料及模擬服務，不使用 API 額度。
