# 測試內容與資料準備

## 固定情境與素材

- 採用 [門票測試劇本](門票測試劇本.md) 的三篇串文、帳號及對話，模擬帳號使用橘色圓形頭貼。只有門票帳號 `@giveme_money` 會進入測試聊天列表及聊天室。
- 第二、三篇日常串文已寫在劇本。門票劇本可參考 [作業一的田野與訪談](https://docs.google.com/document/d/167mzJxtOMmyO0XW3kmQ_oksAXeon7umW4QfVIuF0fXM/edit?tab=t.u8fvt3g89wbe)。
- 只準備一份門票聊天室劇本。先顯示固定歷史訊息，預填「轉好帳了」，受測者送出後逐條顯示賣家的可疑訊息。每則記錄 ID、發送者、文字、順序與出現條件，賣家的句子逐句可勾選。
- 劇本用模擬帳號和資料。若需顯示可疑網址，可用不可連線的示例網域並以純文字呈現。參考截圖用於比對版面。

## 官方案例整理與匯入

1. 先複核試算表中與劇本最接近的門票案例，尤其是轉帳失敗、要求再付款和假客服。也保留其他商品的個案，供小客服測試跨商品檢索。[30 筆候選試算表](官方案例候選30筆.xlsx)
2. 依試算表的「發布日期」和「發布縣市」回查原文。儀錶板以查詢頁展開個案，所以這批案例共用同一個來源網址。若同日同縣市有多筆，用標題或摘要中的具體線索對照原文。[165 打詐儀錶板｜各縣市每日案例](https://165dashboard.tw/city-case-summary)
3. 完成 Neon 初始化與 OpenAI 金鑰設定後，到 `/admin/cases` 填商品類別、案例原文、發布日期、發布縣市。日期可填民國年或西元年。來源機關與網址已預填，可依實際來源修改。試算表的標題、摘要、手法標籤與收錄狀態供複核。儲存時，AI 會依原文產生標題、標籤與卡片短摘要，系統隨即建立檢索向量。列表可展開原文並查看短摘要。[實作與部署教學](實作與部署教學.md)
4. 為測試準備幾組輸入及預期結果，涵蓋「有高度相關個案」、「只有類似手法」和「資料不足」。儲存案例後，到 Widget 核對檢索結果。

後台儲存成功後會加入檢索，案例清單顯示總筆數並包含草稿與已收錄資料。Neon 直接修改後重新整理後台網頁。Widget 實際檢索還會檢查向量、來源與相關程度。

## 上線測試前

- 在 `/admin/accounts` 新增模擬 Threads 帳號 `giveme_money`，填查詢人數 45。命中固定顯示「曾被通報」、45 人及數發部通報按鈕；改案件狀態不改變結果大標。修改後台人數後重新送查，畫面應顯示新數值，其餘文案相同。另查未收錄帳號，應顯示「無法確定」、0 人、「該帳號暫無相關通報紀錄」，並提供帳號查證、對話評估、快速對話與前往通報四個按鈕。兩種結果均沒有案例卡或 AI 回覆。
- 優先準備三筆不同且有來源的門票案例，在後台按「更新首頁案例卡」。驗證首頁只在第一篇門票串文下方顯示這批卡片，首頁與 Widget 都最多顯示三張，資料不足時顯示實際找到的筆數。
- 用「快速對話」測試自由輸入與追問，包括目前商品、改問另一類商品及案例庫不足。核對通常 1～2 段、最多三段，每段約 35～45 字元、最多 48 字元，手機約 2～3 行且完整結句，只說一個具體疑點與下一步，提到連結應有對應查證按鈕；帳號按鈕須與使用者的社群帳號情境及本段帳號查證用途相符。重測「交易施壓、要求解凍、可透過臉書官方管道查」時，應引導對話評估，不能出現無關帳號按鈕；已保存的錯配按鈕也應被隱藏。對話評估按鈕須直接開啟勾選。按鈕只提供三個既有查證工具，不出現通報、封鎖或檢舉按鈕；銀行帳號不得誤配社群帳號查證。按鈕緊接對應段落而非全部集中末尾；案例內容不可直接套成使用者遭遇。第一輪回覆完成後回到對話區頂端；第二輪起，回覆完成後應對齊該輪使用者訊息的開頭，接著往下閱讀該輪回答，不跳回第一輪或停在案例卡。短回覆也應能對齊該輪開頭，仍可手動捲動讀取前文、按鈕與案例；載入中不強制改變閱讀位置。兩功能都先經 RAG 初選，再由 AI 選零至三張，依 AI 順序置底橫向顯示；不適合的候選不顯示。AI 失敗時應只出現一則重試提示，不重複顯示 AI 與請求錯誤。到後台核對問題、分段回答、實際工具按鈕及最終案例。[共用選卡流程](案例檢索與AI選卡.md)
- 測試 AI 全部排除、回傳重複 ID 或不存在的 ID。應去除重複；不存在或超額選卡時提示重試，不回退顯示原始 RAG 候選。RAG 失敗仍可回答，但不附案例卡並保存檢索狀態。
- 未同時設定 AI 與 Neon 時，快速對話只有本機預覽建議，不放固定案例卡；首頁預覽卡不受影響。
- 官方案例聚焦網購、社群買賣、二手商品、門票與周邊交易，不限付款驗證：涵蓋假買家／賣家、假平台客服、超低價或假商品、收款不出貨、退款、物流、索取資料及誘導離開平台等手法。原文需清楚描述「對方要求做什麼、用什麼理由、可能造成什麼損害」。

- 定每場的任務文字和觀察項目，例如是否主動打開 Widget、勾選了哪些訊息、能否說出疑點及下一步。
- 用各自的手機開啟 Demo，核對同一天重整或回聊天室會延續進度；隔天（台灣日期）進入、重整或回到分頁會建立新場次、從頭顯示聊天室，Widget 不帶入前一場對話，舊紀錄仍可在後台查閱。所有環境都沒有「重新開始」按鈕。舊版瀏覽器場次未保存日期，更新後首次進入會建立新場次；既有跨日合併紀錄維持原樣。開啟 Widget 後確認先顯示四種方式。逐一送出並用右下角返回選單，確認未送出的草稿可續填、快速對話可繼續追問。
- 手機檢查 Widget 首頁標題、插圖和介紹固定，僅四個功能按鈕與「如何使用」可上下捲動；使用說明僅框內文字可捲動，圖片、框線、「回首頁」及關閉按鈕不跟著移動。捲軸隱藏但仍可觸控滑動，縮短畫面後仍可到達所有按鈕及說明末尾。按住黃色、黑色按鈕時應立即變色。讀取插圖會預載，切換功能頁和結果時有短淡入動畫，系統的減少動態效果設定應生效。
- 對話評估直接進入訊息勾選，白色選取區、提示和面板四角為 20 px。送出後使用對話插圖，讀取提示文字持續上下跳動；系統啟用減少動態效果時停止跳動。結果列出重點，相關案例顯示在最底下。
- 對話風險必須來自勾選原文＋AI＋RAG，不是訊息 ID。先只勾一般問候，預期線索不足；再勾重複付款與退款承諾，核對較高風險與引用理由。後台原句必須確實出現在本次選取內容，不能借用未選訊息或案例中的情節。
- 另外複核超低價商品、假買家／賣家、防詐提醒、否定句、新網購手法及無案例狀況。模型提示允許未列出的網購手法，案例不足仍可分析；非網購問題引導回查證範圍，模型品質需人工校正。[對話評估驗收說明](對話評估_AI與RAG.md)
- 帳號與連結查證的讀取圈位於標題下方。查核結果採獨立畫面，結論用最大字級。錯誤提示為 16 px 橘色。
- 試送格式無效的網址及模擬連線失敗，確認網址留在輸入欄供修正或重試。未知網址 AI 分析逾時仍保留固定結論；帳號查證不呼叫 AI，資料庫失敗時應提示重試，不顯示成未收錄。對話評估依賴 AI，逾時或拒答時應顯示錯誤並保留勾選，不回傳固定風險。
- 驗證管理員登入後能查閱和編輯。未登入時攔截管理頁與管理讀寫請求。
- 用管理頁核對 Widget 每筆送出的內容與 Bot 回覆是否成對保存。提交紀錄永久保留，開啟和取消勾選等操作不另存事件。
- 用一場試測檢查手機版返回動線、勾選與取消、結果內容、重複提交，以及能否從後台找回這一場的紀錄。

### 連結查證試跑

- 輸入 `123`：在原輸入頁顯示「連結無效，請重新輸入！」，不送出 API，也不進結果頁。
- 輸入 `https://mall.iopenmall.tw/`：未命中 TWNIC 時顯示「暫無疑慮」，黃底與說明帶入 iOPEN Mall，橘字為「可以點開連結」，沒有通報按鈕。
- 從 [TWNIC 本機快照](../data/通報TWNIC詐騙網址彙整表_20261008.json) 選主網域，結果顯示「曾被通報」、黃底「可能涉及網購詐騙」及數發部通報按鈕；不要實際開啟清單網址。
- 換成同主網域的其他次網域、路徑、參數、協定仍應命中；主網域文字只出現在其他網域的路徑、查詢參數或相似名稱時，不應誤判。
- 輸入劇本的 `https://myship.payment-check.invalid/`：顯示「存在疑慮」、黃底「與官方網域不符」及數發部通報按鈕。另用不同品牌別名測試，說明不能永遠寫蝦皮。
- 輸入 `https://www.ilovepdf.com/zh-tw`：顯示「無法確定」。AI 只分析網址字串，不搜尋新來源，不變更結論。通常 0～3 條黃底，每條最多 15 字元；沒有具體疑點時顯示中性黃底「來源仍待確認」。下方說明最多 28 字元、手機最多兩行，不能再出現長篇工具限制說明。
- 「無法確定」下方依序為帳號查證、對話評估、快速對話、前往通報。逐一確認前兩個輸入頁、訊息勾選及快速對話入口都能操作；通報連到數發部。
- 四種結果均按完成提示、大結論、橘字、黃底重點、說明、按鈕排列，沒有網域／來源／狀態三色資訊框、案例卡及「查看其他案例」文字。
- 模擬 AI 未設定、逾時、拒答或產生超過 15 字元的重點或超過 28 字元的說明，仍顯示「無法確定」、中性黃底、短提示與四個按鈕；後台可見 `urlAnalysisStatus` 及實際輸出。
- 本機執行 `pnpm test`：使用本機資料及模擬服務，不使用 API 額度。真實 AI 判讀與手機捲動效果另外實測。

## 效能與等候測試

- 以正式建置／Vercel 測試冷啟動；瀏覽器 Network 應下載兩份 WOFF2，不應下載 TTF。
- 模擬網路長時間無回應：45 秒後應顯示逾時提示、停止載入且保留輸入；重試不建立重複紀錄。
- 開啟作業系統「減少動態效果」，確認淡入、上移、跳動與轉圈均停止；手機按住按鈕仍應立即變色。

## 響應式回歸檢查

- 首頁三張案例載入後，核對 `document.documentElement.scrollWidth` 不大於視窗寬度，避免手機將整頁縮小。
- 逐一檢查 320×568、360×800、375×667、393×852、440×956、768×1024、1280×800、852×393；底部導覽應貼齊視窗下緣。
- 高度 512 px 以下時，Widget 選單捲動區不能為零；四項工具、如何使用及返回／關閉按鈕都應可操作。
- 最新尺寸檢查結果見 [響應式檢查](響應式檢查.md)。
