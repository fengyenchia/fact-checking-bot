## Demo 判定方式

1. **驗證格式**：格式錯誤或解析不到主網域時，在原輸入頁顯示「連結無效，請重新輸入！」，不送出查核。
2. **比對 TWNIC 主網域**：精確命中就顯示「曾被通報」，停止比對。不同次網域、協定、連接埠、路徑及參數不影響命中。[2026-10-08 本機快照](../data/通報TWNIC詐騙網址彙整表_20261008.json)
3. **比對常見電商、物流與售票官網**：HTTPS、預設連接埠、完整網域名稱符合本頁資料時，顯示「暫無疑慮」。文案帶入實際服務名稱，不向使用者顯示「資料庫收錄」或「已知服務清單」。
4. **檢查仿冒線索**：次網域標籤或主網域名稱前後綴含已收錄品牌別名，但主網域不符時，顯示「存在疑慮」，說明帶入實際品牌。例如 `myship.payment-check.invalid`。
5. **其餘網址**：固定顯示「無法確定」。有 API 金鑰時由 AI 分析網址字串，產生短說明與通常 0～3 條黃色重點；每條最多 15 字元、不硬性限制條數，沒有具體疑點時由程式顯示中性黃底「來源仍待確認」，不硬湊疑點。說明最多 28 字元、一句話，畫面最多顯示兩行。

## 結果排版與操作

- 共用順序：完成提示 → 固定大結論 → 橘色建議 → 黃色重點（無疑點時使用中性摘要）→ 說明 → 對應按鈕。
- 曾被通報：黃底「可能涉及網購詐騙」、主網域曾被通報的說明、數發部通報按鈕。
- 暫無疑慮：橘字「可以點開連結」、官網比對結果、服務名稱；沒有通報按鈕。
- 存在疑慮：黃底「與官方網域不符」、動態品牌名稱、數發部通報按鈕。
- 無法確定：AI 重點及短說明；帳號查證、對話評估、快速對話、前往通報四個按鈕。對話評估會直接開啟訊息勾選。
- 四種連結結果均不檢索或顯示案例卡；其他兩種對話功能仍保留案例卡。
- 大標使用 `.text-widget-warning`，黃色重點及說明使用 `.text-widget-body`；圓角 20 px。右下回首頁固定，結果內容可上下捲動。

## 資料與限制

- [判定與固定文案](../lib/server/verification.ts)、[結果元件](../components/chatbot/url-check-result.tsx)、[未知網址 AI 指令與驗證](../lib/server/url-analysis.ts)。
- TWNIC 先解析「網域名稱」，失敗才用「偽冒網址」；精確比對可註冊主網域，不使用網址包含比對。
- 「曾被通報」是主網域命中，固定說明明確寫主網域；不表示完整頁面已做即時檢測。
- 官方短網址只核對原始來源，說明仍提醒轉址目的地待查證。
- AI 僅用於「無法確定」，需要 `OPENAI_API_KEY`，不需要 Neon 才能分析；永久紀錄仍需 Neon。
- AI 沒有搜尋或掃描工具，不補查網站來源，不把陌生、未收錄或缺少 www 當成詐騙證據，不變更大結論。
- AI 未設定、拒答、逾時或格式不符時，保留「無法確定」、固定提示與四個按鈕，使用中性黃底與短提示，不硬湊疑點；後台保存分析狀態。
- 更新 TWNIC 時替換本機 JSON 並重新部署；此次輸出欄位存在原有 response JSON，不用執行新 SQL。
